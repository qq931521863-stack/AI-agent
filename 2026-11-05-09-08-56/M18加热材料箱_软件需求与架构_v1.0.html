一、软件定位与边界

1.1 软件在系统中的位置

固件是"传感器 → 决策 → 执行器 + 显示"的闭环中枢。整机 115 条需求中，约 62 条需要固件参与实现，其中 纯软件实现 31 条、软硬协同 24 条、硬件实现软件仅做呈现 7 条。

1.2 软硬件保护分工（安全相关，必须先划清）

保护项硬件职责软件职责
过温独立温控开关 / 热熔断器（建议必配，作为最后一道）NTC 采样 + 阈值判断 + 锁存关断 + 图标提示
过流 / 短路保险丝或 PTC、MOSFET 驱动限流电流采样 + 判定 + 锁存 + 故障码
加热丝开路—上电脉冲测通断 + 运行中电流为零判定
电池过放电池包内建 BMS 保护欠压阈值提前关断（早于 BMS），保护可恢复性
反接防反接二极管 / MOS不做（硬件保证）
MCU 死机独立看门狗芯片（可选）窗口看门狗喂狗 + 关键任务心跳
铁律：任何故障路径的默认动作必须是"加热输出 OFF"。加热驱动的硬件默认态必须是关断（下拉），软件只能"使能"，不能"维持"。

三、软件架构

3.1 分层架构（5 层，严格单向依赖）

层名称职责不允许做的事典型文件
L5应用层 App三个正交状态机、控温策略、业务规则不直接操作寄存器、不调用 BSPapp_sm_*.c
L4服务层 Service调度器、事件总线、软件定时器、滤波、告警队列不含业务判断sched.c event.c
L3设备层 Device按键、显示、热控、电源、电池、NVM、诊断的抽象设备不出现具体引脚号dev_key.c dev_lcd.c
L2板级支持 BSPGPIO / ADC / PWM / LCD / I2C 的引脚级实现不做业务逻辑bsp_gpio.c
L1芯片 HAL厂商库 / CMSIS—hal_*.c
依赖规则：只允许上层调下层，禁止反向调用与跨层调用（L5 不得直接调 L2）。层间通过头文件接口隔离，便于 SIL 仿真时整体替换 L1/L2。

NVM 写入事件5–20ms参数变更低优先级，可延后

3.4 三层正交状态机（核心设计）

整机 UI 需求里描述了 11 个"状态"，但把它们画成一张扁平状态机会产生 11×11 的转移爆炸。实际它们是三个彼此独立的维度，应该用三个正交状态机并行运行，显示层负责合成。

域 A · 电源域（低频，秒级）

状态进入条件退出条件
A0 OFF关机 / 无电源按键开机 且 有可用电源
A1 ON_BAT无 AC 且有电池插入 AC → A2；电池耗尽 → A0
A2 ON_ACAC 在位拔掉 AC → A1
A3 SHUTDOWN欠压 / 用户关机保存参数完成 → A0

域 B · 温控域（中频，500ms）

状态进入条件退出条件
B0 IDLE未使能加热T ≤ SP − 3°F → B1
B1 HEATING低于回差下沿T ≥ SP → B2；故障 → B4
B2 MAINTAIN达到设定温度T ≤ SP − 3°F → B1
B3 OVERTEMPT ≥ min(85°F, SP+5°F)回落并锁存 60s → B0
B4 FAULT任一硬件故障断电 / 诊断清除

域 C · 交互域（高频，10–100ms）

状态进入条件退出条件
C0 NORMAL默认按键 → C1；5min 无操作 → C2
C1 ADJUST按 ↑ / ↓OK / 5s 超时 → C0
C2 LOWPOWER5min 无操作按键 / 达标 / 告警 → C0
C3 ALARM_LID开盖 ≥ 30s关盖 → C0
合成规则：显示与蜂鸣由 f(A, B, C) 统一计算，优先级为 B4 > B3 > C3 > B1 > B2 > C1 > C2。这样新增一个状态只需改一个域，不会引起组合爆炸。

3.5 关键数据模型（单一数据源）

typedef struct {
    /* 传感器原始与滤波值 */
    int16_t  ntc_raw[2];          /* ADC 原始值 */
    int16_t  temp_f;              /* 滤波后内部温度, °F ×1 */
    int16_t  temp_target_f;       /* 设定温度, °F ×1 */
    uint8_t  unit;                /* 0 = °F, 1 = °C */

    /* 电源 */
    uint8_t  ac_present;
    uint8_t  batt_present[2];
    uint8_t  batt_soc[2];         /* 0-100 */
    uint8_t  active_batt;         /* 0/1 */

    /* 执行器 */
    uint8_t  heat_duty;           /* 0-100 % */

    /* 状态 */
    uint8_t  sm_power;            /* A0-A3 */
    uint8_t  sm_thermal;          /* B0-B4 */
    uint8_t  sm_ui;               /* C0-C3 */

    /* 诊断 */
    uint16_t fault_bits;          /* 位图, 见 E01-E09 */
    uint8_t  lid_open;
    uint32_t run_hours;
} unit_state_t;
设计要点：全局只有一份 unit_state_t，任何模块只读；写入必须通过该模块的 setter 并置 dirty 标志，由显示服务统一刷新。禁止模块各自缓存温度。

3.6 事件机制

typedef enum {
    EV_NONE = 0,
    EV_TICK_10MS, EV_TICK_100MS, EV_TICK_500MS, EV_TICK_1S,
    EV_KEY_PRESS, EV_KEY_RELEASE, EV_KEY_LONG, EV_KEY_COMBO,
    EV_LID_CHANGE, EV_AC_CHANGE, EV_BATT_CHANGE,
    EV_FAULT_SET, EV_FAULT_CLR
} event_id_t;

typedef struct {
    event_id_t id;
    uint8_t    arg0;
    uint8_t    arg1;
} event_t;

void event_post(event_id_t id, uint8_t a0, uint8_t a1);
bool event_get(event_t *out);          /* 主循环中非阻塞取事件 */

中断只负责 event_post，不做业务判断；所有业务在 app_main_loop() 中处理，保证可重入安全与可测试性。

四、关键算法设计

4.1 控温算法

采用迟滞（Bang-Bang）+ 最小驻留时间 + 软启动，不使用 PID。理由：被控对象是"箱体 + 加热丝"，热惯性极大（分钟级），PID 的积分项在 5°F 步进下没有意义，反而会因超调触发过温保护。

T_f = α·T_raw + (1-α)·T_f          /* α = 0.2, 500ms 周期 */

if (T_f <= SP - 3)  want_heat = 1
if (T_f >= SP)      want_heat = 0
if (T_f >= min(85, SP+5))  → 强制 OFF + 锁存 60s

/* 最小驻留 */
if (want_heat != heat_on && (now - last_toggle) < 60s) 保持原状态

/* 软启动 */
heat_duty += (want_heat ? +2 : -5)   /* 每 100ms 步进, 约 5s 到 100% */

4.2 SOC 估算

SOC_ocv = lookup( V_batt + I_load · R_internal )   /* 内阻补偿 */
SOC_t   = compensate_temp(SOC_ocv, T_batt)         /* 低温降容补偿 */
段数 = SOC_t ≥ 75 ? 4 : SOC_t ≥ 50 ? 3 : SOC_t ≥ 25 ? 2 : 1

切换判据独立于 SOC：带载电压低于截止值持续 3s 即切换，避免 SOC 估算误差导致深度放电。

4.3 按键识别（含一处规格冲突）

冲突：UI 规格写"长按每 200ms 步进一次"，同时又要求"UP+DOWN 长按 750ms 切换单位"。若连发在 500ms 就启动，那么到 750ms 时单键已经触发过一次，切单位时会带上一次误调整。
解法：把单键连发起始延时设为 800ms（> 750ms 组合键判定窗口），800ms 后才开始每 200ms 连发。这样组合键永远优先，无需回滚逻辑。

4.4 显示合成

/* 每 100ms 调用一次 */
seg_clear();
if (fault_bits)            render_fault();       /* Err + 码, 2s 交替 */
else {
    render_target(temp_target_f, unit);          /* L1 + 单位 */
    render_internal(temp_f);                     /* L2 */
    render_icons(priority_pick());               /* L3, 单图标优先 */
    render_battery(batt_soc, batt_present);      /* L4 */
}
lcd_flush();

闪烁统一用 phase = tick_1ms % period 计算，保证同屏所有图标同相位，不会出现"两个图标交替闪"的观感问题。

4.5 低功耗时序

阶段功耗动作
正常运行≈ 8mA全速、背光 100%
低功耗显示（5min 后）≈ 5mA背光 10%、仅右下角显示、主频降至 1MHz
STOP（无加热、无告警）≈ 30µARTC 1s 唤醒采样，按键 EXTI 唤醒
加热工作时 MCU 功耗可忽略（加热丝是安培级），所以低功耗优化的重点是不加热时的待机电流——这直接决定"一节 12Ah 电池能否撑 24 小时"。

六、可靠性与安全设计

机制做法目的
Fail-safe 默认态加热驱动硬件下拉；软件复位期间输出恒为 OFF任何异常都导向"不加热"
窗口看门狗喂狗需同时满足"主循环计数递增"与"关键任务标志置位"防止单一任务卡死被掩盖
双传感器互检两点温差 > 10°F 持续 5s 判故障防止单点失效导致持续加热
变化速率限制|ΔT/Δt| > 5°F/s 判异常识别传感器脱焊 / 短路
参数双备份双 Slot + CRC16 + 版本号写入断电不丢参数
复位原因记录上电读 RCC 标志并持久化现场问题可追溯
故障锁存FAULT 态需断电或诊断清除，不自动恢复防止故障反复触发掩盖问题

八、软件侧待确认清单

编号问题影响建议
SW-Q1是否引入 RTOS中当前规模用前后台足够；若加 BLE 再评估 FreeRTOS
SW-Q2防误触开机方案：长按 1.5s 还是机械锁高长按 1.5s（成本低），配合按键凹陷设计
SW-Q3长按连发与组合键的时序冲突高连发起始延时改为 800ms（见 4.3）
SW-Q4调整态 5s 超时是保存还是回退中保存（符合"设完就走"的使用习惯）
SW-Q5蜂鸣音型、音量、是否可静音中2kHz 断续音，OK 键静音 10min
SW-Q6过温阈值取 85°F 还是 SP+5°F高取两者较小值，兼顾材料安全与不误触发
SW-Q7SOC 是否上库仑计中先做电压法；若误差超标再加采样电阻积分
SW-Q8是否需要固件升级能力中预留 Bootloader 分区，首版可不实现
SW-Q9温度基准单位最终取 °F 还是 °C高°F（美国主市场），见整机规格 G-05
SW-Q10是否预留 BLE 硬件低预留 UART 与焊盘，接口层留空实现
