# 2026-10-27

## 修复 Clash for Windows VPN 故障

**环境**：Windows，Clash for Windows 0.20.37（D:\Program Files\Clash for Windows），TAP-Windows 9.24.2，混合端口 7890，系统代理已开启。

**根因（三层）**：
1. 当前生效配置是 **WgetCloud 订阅**（`list.yml` 中 index=1），该订阅节点名内标注「套餐到期日期 2025-05-03」，已过期 → 18 个节点全部 TCP/ICMP 不通。
2. 另有 **iKuuu_V2 订阅**（`profiles/1777432831614.yml`，index=3）仍然有效（到期 2027-01，余量约 200GB，46 节点中 45 个 TCP 可达），但未被选中。
3. iKuuu 服务端会按 User-Agent 判定客户端版本：用 CFW 0.20.37 的 UA 拉取会在配置顶部注入大写键 `Proxy:` / `Proxy Group:` / `Rules:` 的「升级提示」占位块（指向 127.0.0.1:1080）。这些大写键 Clash 不识别、会被忽略，真正的 `proxies:` 段仍在下文，故不影响加载；但用现代 UA（如 `mihomo/v1.18.0`）拉取则完全干净。

**处置**：
- 备份 `profiles/list.yml` → `list.yml.bak-20261027`。
- 将 `list.yml` 的 `index` 由 1 改为 3，切到 iKuuu 订阅。
- 重启 CFW 后加载正常，46 节点中 42 个可用。
- 节点选择：`🇯🇵 日本W03 | IEPL`。实测 ChatGPT 需浏览器 UA 才返回 200（裸 curl 返回 403 是 Cloudflare 机器人拦截，非节点故障）；新加坡/美国节点对 chatgpt.com 超时。出口 IP 212.42.210.69（JP）。

**遗留问题（未改动，需用户决策）**：
- 日志持续报 `ERR [Inbound] start failed error=Error creating interface: Access is denied. type=TUN`。原因是 CFW 未以管理员身份运行，TUN 虚拟网卡创建被拒。系统代理模式工作正常，浏览器等走系统代理的应用不受影响；仅绕过代理的程序（部分游戏/终端工具）无法被接管。
- 修法：给 `Clash for Windows.exe` 加 `~ RUNASADMIN` 兼容性标记（HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers），代价是每次启动弹 UAC。因无法在非交互环境验证，未擅自设置。
- 长期建议：CFW 0.20.37 已停更，iKuuu 已开始提示版本过旧，建议迁移到 Clash Verge Rev / Mihomo Party，可一并解决 TUN 权限与订阅兼容问题。

**工具**：工作区保留 `clash_healthcheck.py`，读取 `~/.config/clash/config.yaml` 中的 external-controller 端口与 secret，输出当前节点、出口 IP 及 6 个站点的连通性。

**注意**：CFW 重启必须用 `explorer.exe "<exe路径>"` 拉起；直接 `Start-Process` 会立即以退出码 0 结束（Electron 单实例/会话限制）。
