1.2 真实的控制链路（这是全篇最重要的一段）

从 CAN 指令到功率管栅极，一共 6 步。每一步我都标了代码位置：

// ① CAN 指令 → 目标电流（mathR02.c:139）

// ② 限功率/限温降额（mathR02.c:144-156）

// ③ 电流给定斜坡（mathR02.c:157）每拍 ±0.0002A，防止阶跃冲击
// ④ 一阶滤波 + PI（mathR02.c:161-163）

// ⑤ 归一化频率 → Hz（mathR02.c:164）

// ⑥ 限幅 → 写 HRTIM 周期（ConsoleFast.c:168）

看懂这条链，你就看懂了 80% 的数字电源软件。PI 的输出直接就是开关频率——这是 LLC 和 Buck 最本质的区别：Buck 调占空比，LLC 调频率。所以 PI 的输出量纲不是"电压"也不是"占空比"，而是"频率"。

1.4 两套控制律并存：这是历史包袱，也是最好的教材

你的固件里同时存在两种调制方式，靠 CtrMode 切换：

定频 + 调占空比

Plv 固定为 40k / 80k / 120kHz，Duty 在 0.02–0.4 之间变。
用于：SoftStar、BmsStar、ConVolt、ConCurPWM。

本质：预充 / 过渡期的限流手段。不是正规 LLC 调制。

PFM（Duty = 0.5）

Plv 在 60k–250k 之间变，Duty 恒为 0.5。
用于：OvLoadPFM（mathR02.c:137）。

本质：这才是真正的 LLC 闭环。名字叫"过载 PFM"，其实是主充电环路。

为什么要有定频调占空比这一段？因为输出要在 30–60V 之间连续可调，预充阶段输出电容是空的，直接上 PFM 会瞬间灌爆。占空比调制在这里被当成"限流阀"用——这是个工程妥协，不是教科书做法。

你要学的不是"照抄这个妥协"，而是理解它为什么存在，然后在新设计里用更干净的方式解决同一个问题（比如：PFM + 频率斜坡 + 输出电流环限幅）。

  • W1　只读三个文件：mathR02.c、Sr_Handle_N.c、ConsoleFast.c。手抄控制链路 6 步。
  • W2　把 CtrMode 8 个状态画成迁移图，标出每个状态的输出。
  • W3　搞清 Plv → preA → PERxR → CMP1..4 的换算，手算 fsw=120kHz 时四个比较值是多少。
  • W4　画 4 个开关状态的电流路径（纸笔），对照仿真波形验证。
  • W5　跑 W2 的代码考古 prompt，让 AI 解释 Kp 表，你去验证。
  • W6　产出：《LLC 控制律一页图》——一张 A4，左边控制链路，右边状态机，底部关键参数表。

Sprint 2（第 7–12 周）：反推你自己的计算书

目标：把第 02 章那张表，用自己的手算和实测复现一遍
  • W7　学 FHA 的两个假设，能说清"为什么方波可以只取基波"。
  • W8　手算 5 个点（fn=0.6/0.8/0.9/1.0/1.2），画在方格纸上。
  • W9　用 llc-gain-curve.html 对齐手算点，理解 k 和 Q 各改什么。
  • W10　LCR 表实测：副边开路测 Lr+Lm，副边短路测 Lr；读 Cr；低压交流测匝比。
  • W11　用实测值重算 fsw 范围，和固件的 60k–250k 对比，解释偏差。
  • W12　产出：《LLC 主参数计算书》3–5 页，格式照 AN-4151。

Sprint 3（第 13–18 周）：小信号与增益调度

目标：能解释 Kp 表为什么长那个形状，并能自己重新标定
  • W13　推导 Gvf(s)：从 fs 扰动到 Vo 响应，理解为什么它在不同 fn 差几十倍。
  • W14　用增益曲线斜率反推"对象增益"，和你代码里 Kp 表倒数对比。
  • W15　在仿真里做扫频（或阶跃），量出实际穿越频率。
  • W16　定目标：穿越频率取 fsw/10，相位裕度 >45°，增益裕度 >6dB。
  • W17　把 PI 离散化，写差分方程，验证抗饱和和限幅。
  • W18　产出：《增益调度标定方法》一页——给定任何一台新机器，怎么标 Kp/Ki 表。

Sprint 4（第 19–24 周）：纸上设计一台新机器

目标：从零走一遍完整流程，不上电，但每个数字都要有出处
  • W19　选一个不同的规格（比如 3.3kW / 200–450V 输出），自己定 n 和 k。
  • W20　出完整计算书，包含器件应力（Vds、Irms、整流管）。
  • W21　在开环仿真里搭出这台机器，验证增益曲线。
  • W22　写控制代码骨架：状态机 + PFM 环路 + SR 时序表 + 保护矩阵。
  • W23　用 W4/W5 的 prompt 让 AI 审计你的状态机和保护矩阵。
  • W24　产出：《LLC 数字电源软件设计包》——计算书 + 仿真 + 代码骨架 + 保护矩阵。

06三件别做的事

别做原因
别通读 4200 行3200 行是通讯、OTA、存储。读它们不会让你更懂 LLC，只会让你在第 3 周放弃。
别把量产代码当规范它是三年现场修补的结果。定频调占空比、110 行注释掉的 OTP、互相矛盾的宏——学它的约束，不学它的形式。
别在没算过之前上电你需要先知道这台机器的容性边界在哪。算不出来就上电，等于闭眼开车。

如果只做一件事：第 10 周那天，用 LCR 表测出 Lr、Lm、Cr、匝比，填进计算器，看它算出的 fsw 范围能不能对上你固件里的 60k–250k。

对上了，你就完成了从"会用"到"会设计"的跨越。对不上，那个差值就是你接下来三个月要研究的东西——而且它是具体的、可验证的，不是"我还没学会 LLC"这种模糊的焦虑。
