这次改的不是排期，是验证手段。上一版把"实测反推"和"上电验证"当成必经环节，那需要公司样机、LCR 表、差分探头——你现在一样都没有。而你有另一样更稀缺的东西：能把 C 代码编译成 DLL，挂进 PLECS 跑闭环。

这条路对你不只是"退而求其次"，它其实是更快的路：仿真里能看到的量，实测根本看不到——磁通密度、每个开关的瞬时损耗、谐振腔内部节点电流、任意故障注入。而且不用等样机、不用抢仪器、不用看别人排期。

代价必须说清：仿真通过不等于实机能跑。模型里没有寄生参数、没有温升、没有 EMI。所以计划里专门有一节"仿真可信度分级"，告诉你哪些结论可以直接用，哪些只能当趋势。

04八个阶段，逐周拆开

S0环境与账本W1 · 5h
这一周只做三件准备。软件工程师对这个流程很熟：先把编译链跑通，再写业务代码。

周任务

  • 2h确认 PLECS 的 C 编译链。PLECS 的 C-Script 有"解释执行"和"编译执行"两种模式，编译模式需要外部 C 编译器（Windows 上通常配 GCC/MinGW）。在 Preferences 里找 Compiler 相关设置，先写一个 Hello World 级别的 C-Script 模块，确认能编译、能跑。这一步不通，S3 全部做不了。
  • 2h建三列参数账本。列改成：理论值 / 仿真值 / 实机值（最后一列长期留空）。8 个关键参数先填理论值，来源写清是丝印还是反推。后面每验证一次，就在"仿真值"那列填一个数，并记偏差。
  • 1h把现有两个模型各跑一遍，截图存档。不改参数，只看现状——记录当前模型的 Vo、fsw、效率、SR 是否启用。这是你的"基线"，后面所有改动都要和它比。
交付物：一张能编译 C-Script 的截图 + 三列账本（理论列填满）+ 两份基线运行记录。
验收：能说出"我的 PLECS 用的是哪个编译器、编译模式怎么开"。说不出来，先解决这个，别往下走。
S1虚拟样机：先让开环跑对W2–W4 · 15h
把仿真模型改造成"等于你设计书里那台机器"，然后用 FHA 校核它。开环是唯一能干净对照理论的工况——闭环会把误差藏进环路里。

周任务

  • W2改参数，对齐设计书。C22 从 200nF 改 136nF，母线设 380V，n=4、Lr=12µH、Lm=80µH。先跑 PWM 开环那个模型，扫 60k–250k，每 5k 记一个 Vo。改完先看 fr 是不是落在 124.6kHz 附近——这是模型对不对的第一道关。
  • W3和 FHA 叠图。把仿真点导成 CSV，与 llc-gain-curve.html 的理论值画在一张图上。看三件事：分叉点在哪、分叉方向是高还是低、fn=1 附近是否重合。典型结果是满载区仿真略低于 FHA（死区与压降），轻载区偏差更大。
  • W4补上同步整流模型。这一步是新增的重点：确认副边用的是"MOSFET + 体二极管"模型而不是理想二极管，加上栅极驱动信号（由副边电流过零 + 延时决定）。先把 SR 设成"永不开通"，跑一遍；再设成"理想时序"，跑一遍，对比效率差多少。这个差值就是你后面要优化的空间。然后做 M1。
交付物：一张"仿真 vs FHA"叠图 + 一张 SR 开/关的效率对比（两个工况即可）+ 三句话结论。
验收：能回答"为什么仿真在满载区比 FHA 低"。答"因为损耗"不算答对，要说出是哪种损耗、在哪个区间更明显。
S2闭环：PI 与 PFM 怎么咬合W5–W8 · 20h
这一阶段的目的不是"跑出稳定输出"，是亲手体会"PI 输出就是频率"这件事。你在代码里见过 flvOut = out×50000，但只有自己搭一遍，才知道那个 50000 是怎么来的。

周任务

  • W5用 PLECS 自带模块搭 PI + 限幅 + 周期换算。不要一上来就写 C。先用传递函数模块搭，把 Vo误差 → PI → 频率 → 周期 → 占空比 这条链跑通。重点：给 PI 输出加限幅 60k–250k，看限幅触发时输出怎么失守。
  • W6测环路。做三件事：① 负载 10%→100% 跳变，看恢复时间和过冲；② 母线 380→410V 跳变，看抗扰；③ 扫 PI 的 Kp/Ki，画出响应面。你会看到"Kp 太大就振荡、太小就慢"这条老规律，在 LLC 上还多一层——Kp 必须随频率变。
  • W7验证"为什么 Kp 要随频率变 130 倍"。把 M_CoeffiFp 表的几个点（102kHz 的 0.0018、300kHz 的 0.24）代进去，分别在对应频率下测阶跃响应。如果固定一个 Kp 跑全频段，一定会在某一端振荡或迟钝——这就是那张表存在的理由。
  • W8加 SR 闭环时序。让 SR 的开关由副边电流过零检测 + 延时决定，扫延时值看效率与直通风险。这一步要小心：SR 时序错了会直通，仿真里表现为电流尖峰暴涨——这正好是你要学会识别的现象。
交付物：三条响应曲线（负载跳变 / 母线跳变 / Kp 扫描）+ 一段"为什么 Kp 要随频率变"的解释（300 字）+ SR 延时-效率曲线。
验收：能说出"如果把 M_CoeffiFp 表全部改成同一个值，会在哪个频段先出问题"。这是理解增益调度的标志。
S3DLL 在环：把真实控制代码挂进仿真W9–W13 · 25h
整条路线的技术制高点，也是你比硬件工程师强的地方。目标：不是"仿真里有个 PI"，而是仿真里跑的就是你写的那份 C 代码。做到这一步，改一行代码就能看波形变化，这比读一百遍代码有用。

周任务

  • W9定接口。列出 DLL 需要哪些输入、哪些输出、哪些状态：输入是 Vo、Io、Vin、故障标志；输出是 PWM 周期与占空比、SR 使能；状态是 PI 积分、状态机、计数器。写成一张表，先纸上定，别急着写代码。
  • W10抽核心逻辑，写成独立 C 模块。从 mathR02.c 抽三块：PI + 限幅 + 频率换算、状态机、SR 时序。**去掉所有 HAL 和寄存器操作**，只留纯计算。这一步做完，你会第一次看清"控制逻辑"和"硬件操作"其实是两层。
  • W11编译成 DLL，挂进 PLECS。用 C-Script 的编译模式或 DLL 模块，把模块接上。第一次跑大概率不工作——常见原因是端口顺序、数据类型（int/double）、初始化顺序。用最简单的开环测试先验证通道通不通，再上闭环。
  • W12对齐。同样的负载和母线，DLL 跑出的稳态波形要和 S2 里 PLECS 自带控制器基本一致（Vo 误差 <2%，fsw 误差 <3%）。不一致就查：是 PI 参数不同、是限幅不同、还是采样延时不同。这个"查差异"的过程，就是你把代码读透的过程。
  • W13加故障与保护。把 ProtectionLLC.c 的阈值表搬进去：过压、欠压、过流、过温、SR 直通。逐个注入验证动作。然后做 M2。
交付物：一份可编译的 C 模块（含接口说明）+ 一张 DLL vs 自带控制器的对比波形 + 一张"故障注入-动作"对照表。
验收：改一行 PI 参数，重新编译，波形在 5 分钟内发生变化。做到这个，你就有了一个"可以随便试"的实验台——这是整个计划里最值钱的能力。
S4整机联调：母线不再是理想源W14–W18 · 25h
之前所有仿真都假设母线是理想电压源。真实整机里，母线有 100Hz 纹波、有内阻、有动态跌落。"整机"和"单级"的区别全在这里。

周任务

  • W14搭 PFC 级。先用平均模型（快，够看动态），母线设 380V 带 100Hz 纹波（幅度按 5–10V 估）。看 LLC 的环路能不能抑制这个纹波——输出纹波会直接反映 PFC 纹波的传递率。
  • W15母线动态。做三个场景：① 输入 90V 低压满载（母线跌到 360V）；② 264V 高压轻载（母线升到 410V）；③ 输入掉电 20ms（母线跌到 300V 以下）。第③个场景是实机最容易炸的，仿真里先看一遍。
  • W1630–40V 硬开关段。把 Duty 从 0.02 扫到 0.40，验证 §5.4 的模型；再抓 40.2V 交接瞬间，看有没有电压台阶。这是设计书里唯一还没被验证的推断，仿真能给你第一手答案。
  • W17故障注入。按清单逐个打：输出短路、SR 直通、母线跌落、负载突变、过温。记录每个故障下 DLL 的动作是否符合预期。重点看"故障恢复"——能不能自动重试，还是会锁死。
  • W18全角点跑一遍。Vin × Vo × 负载 的组合矩阵，记录每个点的 fsw、效率、峰值电流、磁通。这张表就是你后面写设计书的底气。
交付物：整机模型（含 PFC 与 SR）+ 全角点工作点表（20 行以上）+ 故障注入记录 + 40.2V 交接结论。
验收：能说出"这台机器在哪个工况最危险"。如果答案是"60V 满载"，并且能说出是磁通还是电流应力，说明你真的看懂了。
S5参数标定：把"调参"变成"算参"W19–W22 · 20h
前面是"看懂"，这一阶段是"会改"。目标：给你一个性能指标，你能算出该动哪个参数、动多少。这就是"能维护"和"能设计"的分界线。

周任务

  • W19Kp/Ki 响应面。在 DLL 里扫 Kp × Ki 的网格（每维 5 个点，25 组），记录超调、恢复时间、稳态误差。画成热力图，你就能看见"可用区"在哪。
  • W20SR 时序优化。扫开通延时、关断提前量，看效率与直通裕度。产出：一张"延时-效率-裕度"三维表，选出最优区。
  • W21保护阈值标定。每个保护阈值都要回答两个问题：动作够不够快、会不会误动作。用仿真扫边界，找出"刚好不误动"的值。这一步能解释为什么代码里那些阈值是现在这个数。
  • W22写标定报告，然后做 M3。把三张表合成一份"参数-性能"手册：给定指标 → 该调什么 → 副作用是什么。这是你最该带走的东西，比设计书更实用。
交付物：Kp/Ki 热力图 + SR 时序三维表 + 保护阈值标定表 + 一份标定手册（3–5 页）。
验收：能回答"客户抱怨轻载纹波大，你调什么、调多少、代价是什么"。答得出，这一阶段就过了。
S6磁件与损耗：仿真能算的部分W23–W26 · 20h
没有实机，磁件靠仿真 + 解析算。能算的是磁通、气隙、损耗、温升趋势；算不了的是绕法、层间电容、工艺分散性。把界限划清，别在这里陷进去。

周任务

  • W23磁通与饱和。在 PLECS 里读变压器磁通波形，算 60V 满载时的 Bmax（Ae 先按 PQ4035 的 ≈190mm² 估）。目标：确认是否贴住 100°C 的饱和点（0.42–0.45T）。这是全机最紧的一项。
  • W24损耗分解。用 PLECS 的热描述或手算，把损耗拆成：开关损耗、导通损耗、磁芯损耗、铜损、SR 损耗。看哪一项占大头——通常是磁芯损耗和 SR 损耗，这会决定你后面优化谁。
  • W25磁芯选型与气隙。给定 Lm=80µH、Lr=12µH、匝比 4:1，算需要多少匝、多大气隙、AL 值多少。这一步是纯计算，不需要实物。
  • W26写磁件规格卡。两页：磁芯型号、匝数、气隙、线径、绕制要求（三明治、层数）、预计损耗与温升。这份东西到 S8 做实机时直接能用，也可以拿去问供应商。
交付物：Bmax 校核记录 + 损耗分解表 + 磁件规格卡（2 页）。
验收：能说出"这台机器的磁件如果重做，最该改哪一个量"。说不出，说明 W23 只是抄了数，没算。
S7独立设计：给新规格从零走一遍W27–W32 · 30h
这是唯一的真验收：换一个功率和电压等级，不查旧答案，从规格推到仿真闭环跑通。走完才算"会设计"。

周任务

  • W27自选规格并冻结。建议 600W / 48V / 400V 母线 / 恒压恒流。刻意换功率等级和输出电压，避免下意识套用旧参数。写一页规格书，含全部边界。
  • W28定 n、k、fr。按设计书 §6–8 的三条判据：峰值增益要够、地板要低、环流可接受。产出取舍表，写清每个选择的代价。
  • W29工作点表 + 器件选型。全角点扫一遍，确定开关管应力、谐振电容耐压与电流、SR 选型。这一步会逼你面对"参数一改，应力全变"的连锁。
  • W30搭新模型，先开环。照 S1 的流程重搭一遍，用 FHA 校核。你会发现这次快得多——因为你已经知道该看哪里。
  • W31挂 DLL，跑闭环。复用 S3 的 C 模块，只改参数。如果改参数就能跑通，说明你的模块抽象是对的；如果改不动，说明 S3 的接口设计有问题——回去重构。
  • W32写设计书 + 自评审。六到八页：规格、推导、工作点、应力、软件映射、风险。然后做 M4。
交付物：一份完整的新设计书（6–8 页）+ 一个能跑通的新仿真模型 + 一份软件设计说明。
验收：把设计书给懂行的人看，他能挑出细节问题，但没有一条是"这个方向错了"。挑细节说明及格，挑方向说明还要再来一台。
S8实机验证：最小可行的一台W33–W38 · 30h（支线）
不要一上来做 1600W。做一台 100W 级别的验证板，验证三件事：ZVS 有没有、SR 时序对不对、增益曲线和仿真像不像。这台板子的意义是"证明仿真没骗你"，不是"做出产品"。

周任务

  • W33选型与 BOM。100W / 24V 输出 / 400V 母线。器件可以买模块（半桥驱动 + 谐振电感 + 变压器成品），不必自己绕。预算控制在 ¥800 以内。
  • W34买仪器。现在才需要：手持 LCR 表（¥400–600，测 Lr/Lm/Cr）+ 高压差分探头（¥1500+，安全底线）。示波器如果公司能借就借。
  • W35搭板 + 静态检查。先不上电：量驱动供电、量死区、确认母线电容放电回路。这一步不许省。
  • W36低压上电，开环。母线先给 50V，看能不能起振、看谐振电流波形。和仿真波形对比——这是"仿真可信度"的最终检验。
  • W37闭环 + SR。挂上控制代码（可以就是 S3 那份，移植到 MCU），跑恒压，再开 SR。看效率和仿真差多少。
  • W38写对比报告。仿真 vs 实测：增益曲线、效率、SR 时序、ZVS 裕度。差在哪，就是模型缺了什么。这份报告比任何设计书都值钱。
交付物：一台能跑的 100W 样机 + 一份"仿真 vs 实测"对比报告。
验收：仿真与实测的效率差在 5 个百分点以内、增益曲线趋势一致。差太多不可怕，可怕的是不知道为什么差。
这一阶段可以不做。S7 结束时你已经达成"独立设计"。实机是加分项，什么时候有预算和整块时间再做。不要因为想做实机而拖住主线。

06仿真可信度分级

这一节比任何技术细节都重要。仿真的危险不在于不准，而在于你不知道哪里不准，然后把结论当事实用。下面这张表贴在墙上，每次下结论前看一眼。

A 级
可直接用
能信：增益曲线形状、工作点频率、ZVS/容性区判定、环路稳定性趋势、状态机逻辑、SR 时序因果关系、保护动作顺序
不能信：绝对值精度（±5% 以内可接受）
B 级
看趋势
能信：损耗分解比例、效率相对高低、温升趋势、磁通峰值量级、SR 延时-效率曲线形状
不能信：损耗绝对值（±30%）、结温绝对值（±20°C）、效率小数点后一位
C 级
只做定性
能信："会不会振荡"、"会不会直通"、"会不会饱和"这类是非判断
不能信：任何尖峰幅值、振荡频率、EMI 表现、寄生参数效应、器件应力峰值

举个具体例子：仿真算出效率 94.2%，你只能说"这台机器效率在 94% 量级"（B 级）。但仿真说"60V 满载时磁通贴住饱和"（A 级判定），这个结论要当真——因为它是几何与电压决定的，不依赖模型精度。

09风险与退路

风险一：PLECS 的编译链配不通，DLL 挂不上。
这是 S3 的硬卡点，也是最可能出问题的一步。
退路：先用 C-Script 的解释模式跑通逻辑（慢 10–100 倍，但功能一样），把"验证代码逻辑"和"跑得快"分开。逻辑对了再解决编译。实在不行，用 PLECS 自带控制器 + 手写状态机，牺牲"代码在环"这一项。
风险二：仿真太理想，结论拿到实机上不成立。
这是仿真驱动路线的固有缺陷。
退路：严格执行"可信度分级"——A 级结论才写进设计书，B 级只写趋势，C 级只做是非判断。另外：每个关键结论都用两种方法交叉验证（FHA + 仿真、解析 + 仿真），两者都对才敢用。
风险三：没有实机，学到的东西"悬在空中"。
仿真跑得再顺，摸不到板子会有虚的感觉。
退路：把 S8 提前到 S6 之后，先做一台 100W 小板。但代价是主线被打断，且要提前花 ¥2000+。建议先按原顺序走，S7 之后再决定。
风险四：工作挤占，连续几周没时间。
项目到量产节点就是这样。
退路：砍 S6–S8，只走 S1–S5（21 周）。这已经能"打通并理解整机闭环"，是多数电源软件工程师的水平。剩下的明年再补。

10三件别做的事

这三条能救你
  1. 不要为了"仿真更真"而无限加细节。寄生电感、结电容、驱动电阻——加一个就要调半天，收益递减。加到"能解释你关心的现象"就停。模型的目的是回答问题，不是复现现实。
  2. 不要在 DLL 里复刻整个工程。你只需要 PI、状态机、SR 时序、保护四块。把 HAL、通讯、Flash、看门狗全部剥掉——它们对仿真没有贡献，只会让编译失败。
  3. 不要跳过 S2 直接上 DLL。先用 PLECS 自带模块把闭环跑通，你才知道"对"是什么样。没有基线的对比，等于没有对比。

11明天就能开始的第一步

只做一件事：打开 PLECS，写一个最简单的 C-Script 模块，确认它能编译、能跑。

不用写控制逻辑，就写 y = u × 2 这种。目的是确认你的编译链是通的。这一步不通，S3 那五周全部做不了；这一步通了，后面只是工作量问题。

如果编译报错，把错误信息记下来——这是你在这条路上遇到的第一个真正的技术障碍，解决它比读十页书有用。
